## 系统总体方案

本项目由三部分组成：

1. **Go 后端服务**
   - 提供 REST API（身份认证、聊天房间与用户管理）以及 WebSocket 聊天通道。
   - 统一使用 Gin 框架处理 HTTP 请求，采用内存存储实现 Demo 级别的数据持久。
   - 通过 `Hub` 组件集中管理 WebSocket 连接，按房间分发消息并广播。
   - 管理端接口具备基础鉴权机制（基于管理令牌），支持房间和用户的增删改查。

2. **Flutter 客户端（GetX 架构）**
   - 面向普通用户，实现注册 / 登录、房间列表、聊天界面。
   - 通过 REST API 获取基础数据，并使用 WebSocket 与后端实时通信。
   - 使用 GetX 进行状态管理（控制器拆分：认证、房间、聊天），保持界面响应式更新。

3. **后台管理界面**
   - 与 Flutter 客户端共享同一工程，通过角色区分实现管理能力。
   - 提供房间、用户列表，支持启用 / 禁用用户、创建 / 下线房间等操作。

## 模块划分

### Go 后端

- `main.go`：程序入口，加载配置、初始化依赖并启动 HTTP 服务。
- `internal/config`：配置结构体与加载逻辑（环境变量 / 默认值）。
- `internal/store`：负责内存数据存储，包含用户、会话、房间、消息缓存。
- `internal/ws`：`Hub`、`Client` 等 WebSocket 核心组件。
- `internal/http`：路由注册、控制器实现，包含认证、聊天、管理等 handler。
- `pkg/auth`：简单的令牌生成与校验逻辑。

### Flutter 客户端

- `lib/main.dart`：应用入口，初始化依赖与路由。
- `lib/app/routes`：路由配置与中间件（权限检查）。
- `lib/app/data`：数据模型、API 客户端、存储工具。
- `lib/app/modules`：
  - `auth`：登录注册流程与状态。
  - `home`：房间列表与导航。
  - `chat`：WebSocket 消息收发。
  - `admin`：后台管理界面。
- `lib/app/widgets`：复用 UI 组件。

## 数据流

1. 用户通过 REST API 注册 / 登录，后端返回访问令牌。
2. 客户端持令牌访问房间列表，选择房间后通过 `ws://host/ws?token=...&room_id=...` 建立连接。
3. WebSocket 消息结构统一为 JSON，包含消息类型、发送者、内容与时间戳。
4. 管理员在后台界面调用管理员 API，对用户和房间进行管理；相关变动通知由 Hub 广播至对应房间客户端。
